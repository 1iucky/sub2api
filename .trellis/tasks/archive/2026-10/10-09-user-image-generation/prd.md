# 普通用户生图控制台

## 目标与价值
普通用户在现有控制台内选择生图分组、Key、模型和参数，输入提示词生成、预览和下载图片；可查询持久化历史，管理员可配置图片保留和清理周期。首期接入 OpenAI/GPT、Grok，按既有网关权限、调度与分组计费运行，后续模型和协议可扩展。

## 用户确认的需求
- R1：新增普通用户生图页面，支持模型、分辨率及模型适用参数选择。
- R2：提供提示词输入框、生成中状态、结果预览和图片下载。
- R3：接入本项目生图分组，复用底层鉴权、调度、限制和计费逻辑。
- R4：默认生图分组由管理员配置；用户选择其他配置分组时，按实际所选分组的现有定价、倍率、余额/订阅规则计费。
- R5：调研 GitHub 高星开源生图页面并集成改造，统一当前系统风格，保留来源和许可证。
- R6：用户已授权创建任务和开展规划；用户于最终规划后明确授权开始实施，并要求尽量降低后续 upstream/main 合并冲突。
- R7：不能固定 GPT；首期支持现有 OpenAI/GPT、Grok，提供能力描述及适配扩展机制。
- R8：不自动创建 Key。在生图分组选择旁提供快捷创建按钮，复用现有 API 密钥创建表单；用户可选择自己在该分组的 Key，成功创建后可直接使用新 Key。
- R9：生图页面支持持久化历史查询和保留期内图片下载，刷新或重新登录后仍可查询历史记录。
- R10：管理员可自定义历史图片保留时长、清理执行周期及启停；后台执行删除并处理失败重试。用户已确认到期只删除图片文件，其他历史元数据保留，包括提示词、模型、参数、生成时间、费用及资产清理状态；本清理策略不删除历史记录或账务。

## 代码证据与技术约束
- F1：已有 Images 网关及 OpenAI/Grok 分发，见 `backend/internal/server/routes/gateway.go:82`、`:259`、`backend/internal/handler/openai_images.go:21`、`backend/internal/handler/grok_media.go:21`；完整流程包含权限、并发、审计、调度和计费，不能仅调用转发服务。
- F2：生图权限为 `allow_image_generation`（`openai_images.go:98`）；默认/可选分组须活跃、已启用生图且用户有权限。专属、订阅权限仍由原系统校验。
- F3：独立图片倍率解析见 `backend/internal/service/image_billing_multiplier.go:3`；按张和 token 模式有不同计费分支（`openai_gateway_usage.go:602`）。`handler/gateway_key_billing.go:33` 仅返回 token 倍率，不作为独立图片倍率展示来源。
- F4：未发现控制台专用默认生图分组设置；现有默认订阅配置（`settings_view.go:181`、`frontend/src/views/admin/SettingsView.vue:3935`）和平台账号自动绑定（`admin_account.go:500`）用途不同。
- F5：JWT 与 API Key 分属不同鉴权路径（`frontend/src/api/client.ts:53`、`backend/internal/server/middleware/api_key_auth.go:56`）；生成使用用户选定 Key，历史查询/下载使用本人 JWT，不因原 Key 删除而失去历史。
- F6：现有异步任务是默认 24 小时 Redis 数据（`backend/internal/service/image_task.go:25`），仅启用对象存储时提交（`handler/image_task_handler.go:33`）；不能替代持久化历史。现有 runner 调用原 Images handler（`:211`、`:223`），可提取共享执行机制。
- F7：现有 `/batch-image` 是 Gemini 批量任务及指南，权限入口不同（`frontend/src/router/index.ts:251`、`frontend/src/composables/useBatchImageAccess.ts:16`），本期保留。
- F8：模型目录不是授权；须保留分组白名单、模型映射和账号能力语义（`handler/model_catalog_handler.go:20`、`handler/gateway_handler.go:1187`、`service/gateway_service.go:1393`）。首期 Images 不接入 composite 分组。
- F9：Key 创建/编辑表单嵌在 `frontend/src/views/user/KeysView.vue:470`，平台 watcher（`:1549`）可能清空预选分组；需提取真实共用组件并保持普通密钥页的全部字段、校验和编辑行为。
- F10：现有 `service/image_storage.go` 只返回 URL，`repository/image_storage_s3.go` 未提供持久对象读删契约；历史必须存稳定存储键。部署已挂载 `/app/data`，数据目录解析见 `internal/setup/setup.go:45`。
- F11：清理调度、动态设置、跨实例锁可参考 `service/ops_cleanup_service.go:90`、`:183`、`:363`；存储删除失败和成功状态可参考 `service/batch_image_cleanup.go:224`，不能直接把 Gemini 批量清理当作控制台图片清理。
- F12：Ent schema 是业务表源定义；新迁移需排在实施时最大 SQL 文件之后，不改已发布迁移。当前最大数字前缀为 241，见数据库规范及研究文件。
- 工作区原有首页、规范、测试和镜像包改动必须保留；实施使用独立受管 worktree，原 master 工作区不写业务代码。

## 本期范围与技术方案
包含管理员配置多个生图分组/默认项、手动 Key 选择与共用创建表单、能力驱动参数、文生图、预览下载、持久历史和定时清理；包含明暗主题、移动布局和中英文。

由服务端在经过 Key 鉴权的控制台生图入口创建数据库记录，复用既有网关异步执行并保存结果；历史按登录用户分页查询，支持时间、分组、模型、状态和提示词关键词筛选。初期采用现有持久数据目录中的受管文件存储，不要求额外配置 S3；使用存储接口保留后续扩展空间。多副本需共同挂载同一存储目录。图片保留期建议 30 天、每日 03:00 清理、Asia/Shanghai 时区；清理开关升级缺省关闭，这些建议参数纳入最终方案审核。

不包含图片编辑/参考图/遮罩、视频、无限画布、Gemini 批量任务改造；不承诺从旧计费日志恢复未存储图片，也不默认为全部外部 API 调用存档。首期不承诺进程崩溃后的生图自动重放；恢复为“结果未知”，不得自动再次生成或扣费。

## 可观察验收标准
- AC1（R1/R2）：导航可进入生图页，选择分组、有效 Key、模型、适用参数，提交提示词后展示状态，成功图片可预览并下载，文件 MIME 与实际格式一致。
- AC2（R1/R3）：无 Key、无模型、权限不足、余额不足、限流、上游失败和保存失败均有明确状态；不发送模型不适用参数。
- AC3（R3/R4）：实际生成使用所选 Key 的原用户/分组与原计费流程；按张/token 模式、独立图片倍率、余额/订阅行为保持一致。查询、轮询和下载不产生生图扣费。
- AC4（R5）：真实移植的源码有固定 commit、文件、版权和 MIT notices；页面复用现有 AppLayout/控件、主题和中英文，明暗及移动布局可用。
- AC5（R7）：OpenAI/GPT 和 Grok 均可通过真实网关执行；切换能力时清除无关字段，Grok 不接收 GPT 专用背景等字段。新同协议模型可配置能力档案，新协议新增网关和注册适配器后复用页面。
- AC6（R8）：进入、刷新、切换分组不调用 Key 创建；按钮打开与密钥管理页相同表单，正确预选分组及平台。取消不创建；成功刷新对应列表并选择新 Key；若用户在表单中改选其他分组，不把该 Key 误绑当前分组。
- AC7（R3/R8）：创建沿用原权限、数量/频率限制和全字段校验；停用/过期/耗尽 Key 不被自动替换，双击不重复提交；普通密钥页创建/编辑及引导保持正确。
- AC8（R2/R9）：历史由服务端产生并按 user_id 隔离；刷新/重新登录可分页过滤和查看详情，历史保留提交时分组/模型/参数。Key 删除、切换或默认组变更不改变旧记录归属。
- AC9（R6）：最新 PRD、设计、实施步骤及上下文已保存，最终规划摘要审核之后才开始业务代码实施。
- AC10（R9）：保留期内图片经 JWT 所属检查后可预览/下载；即使临时 URL 过期或原 Key 删除仍能读取；他人 ID、非法路径、非图片内容不可读；图片已清理后显示“图片已清理”，停止预览和下载，原提示词、模型、参数、时间和费用仍能查询。
- AC11（R10）：管理员保存启停、保留天数、调度及合法时区后生效；跨实例不会重复认领清理。仅删除达到期限的受管终态资产，不删除进行中图片、其他文件、历史元数据或计费日志；删除失败可重试，成功删除才标记已清理。图片到期后历史行和原有元数据内容仍存在，费用状态及关联保持可查询。
- AC12（R3/R9/R10）：提交响应丢失、上游成功但存储失败、服务重启等情况不自动重生图；部分成功图片可下载，费用只从既有使用记录关联，未结算/未知不能显示为免费。
